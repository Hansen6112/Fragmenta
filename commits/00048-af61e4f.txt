Phase 1, step 1f-iii: low-health/on-hit-taken triggers become reactions
Handoff §4: "Low-health and on-hit-taken triggers (lowHealthTriggerChecks,
checkEnemyLowHealthTriggers, applyEnemyOnHitTakenPassives) become
reactions with those triggers."

checkEnemyLowHealthTriggers and applyEnemyOnHitTakenPassives already
satisfied this: both dispatch generically off a declared trigger field
("survivedBelowPct" / "onHitTaken") read from creature.passives, never
naming a specific passive. Disclosed via a comment on each rather than
changed, since there's nothing left to do -- they already match the
"behaviour lives in definitions... nothing checks which reaction is
running" shape this step asks for.

lowHealthTriggerChecks (the player side) did not match that shape: it
was a hardcoded spread list of 16 named function calls. Replaced with
a declared LOW_HEALTH_REACTIONS table (id + trigger: "lowHealth" +
resolve), generically iterated in the same order -- each of the 16
check functions (checkHoldTheLine, checkRootedResolve, the 14
checkAvatarOf* functions, etc.) keeps its own body completely
untouched (own threshold, own oncePerFight flag, own effect); only the
dispatch shape changed, from naming each call inline to reading a
table. Zero behavior change: same functions, same order, same
arguments.

whole-fight harnesses (boss_sweep.js, plus3_run.js) bit-for-bit
