Loot Reachability Fixes v2: Regalia retag, worn-gear drops, job-item wiring, audit source rules
Every numeric claim in the handoff was independently verified against
live source before implementing (72 tier-8 items, 87 covered creatures,
100 worn tier-5/6 monster items, 148 unwired job items — all exact
matches), per this engagement's standing verify-before-implement practice.

- Divine Regalia (72 tier-8 items, all 12 "Regalia of ..." sets): source
  "monster" -> "devotion_quest". They were never reachable as "monster"
  (COMBAT_LOOT_POOL only ever delivers tier <= 4); devotion-tracker
  quests don't exist yet. COMBAT_LOOT_POOL no longer has a tier 8 at all.

- rollCreatureLoot (data/items.js): a new wornItemsFor(creature) helper
  flattens resolveEnemyEquipment(creature, creature.level) (trinket
  arrays count each item). An equipped creature's kill loot is now one
  random piece from its own worn gear, or nothing — never the general/
  regional wildlife pools, which stay wildlife-only (confirmed: Legion
  Hound, with a level band but no equipment, is unaffected). Covers all
  86 codex humanoids with level bands plus Dregnar Ashvein (special,
  flat equipment). The 100 tier-5/6 items this makes reachable (all
  already worn by some creature, none orphaned) are retagged "monster"
  -> "enemy_gear"; Dregnar's own 10 keep "world_boss".

- jobs.js LOOT_BY_TIER: added the 148 "job"-sourced items that were in
  neither LOOT_BY_TIER nor REGIONAL_JOB_LOOT_POOL (18 tier-2, 117
  tier-3, 13 tier-4 — generated by script, not transcribed by hand).
  The 13 tier-4 items were added to both key 4 and key 5, since key 5
  already held only tier-4 content; flagging that as my own reading of
  the handoff's "key `4` and `5`" instruction, in case a split rather
  than a duplicate was intended.

- tools/audit.js: replaced the old name-search reachability fallback
  (which let a comment mentioning an item's name count it as "reachable"
  — the exact false negative the handoff called out) with a real
  live/reserved source classification: R1 (an unrecognized source), R2
  (a live source nothing actually reaches, built from the real pools —
  including a worn-gear pool built from BESTIARY equipment/
  equipmentBands), R3 (a "monster" item above the tier-4 cap). Prints a
  live-reachable count, a reserved-by-source breakdown, and the R2 list
  every run.

Verified: regenerated a fresh 1000-kill-per-creature simulation (Watch
Captain ~21.7% own-gear drop vs. the handoff's ~20%, bandit cutthroat's
low band never leaking the high band's gear, Dregnar ~31.8% vs. ~32%,
wildlife/Legion Hound unaffected), sampled job/dungeon rewards for the
newly-wired items, injected a misspelled source to confirm R1 actually
fires then reverted it, and re-ran combatsim.js plus the existing
downed-system/ally-protection/Injury-System ledgers (all clean, combat
stats/gear are untouched by this change).

Two things surfaced by the corrected audit, outside this handoff's
stated scope, worth a look: 8 pre-existing "companion"-sourced items
(the Ascended Bloodbound Champion set, two others) that no ALLY_DEFS
equipment actually references, and this session's own two just-added
"crafted" Injury System items ("smelling salts", "a field splint kit"),
which were always known to need a recipe pass — both are real R2
violations the old audit's name-search blind spot was hiding.
