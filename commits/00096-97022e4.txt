Damage Types spec v1.0, step 2 follow-ups, A5: creature elementVariants
The Codex makes dragons and Elementals "come in elemental variants"
(white Draven-Drak breathes Frost, black breathes Acid, and so on) --
today one shared Breath Weapon burns for every dragon, a gap Tyler's
own spec missed. A5 adds the mechanism, behind DAMAGE_TYPES_V2 (still
off), plus the confirmed variant data from 5_variants.csv.

- js/data/damagetypes.js: pickElementVariant (weighted pick, default
  weight 1), and resolveDamageType's new "fromCreature" priority --
  an ability declaring damageType: "fromCreature" reads whichever
  elementType the wielding creature's own picked variant set, ahead
  of every other priority in the chain.
- js/engine/combat.js: buildFightCreature picks one elementVariants
  entry at spawn time, setting elementType/variantStatus/display
  name and an automatic Resist tag to its own type.
  resolveEnemyActiveAbility's abilityCtx now carries the ability's
  own damageType, and overrides `inflict`'s status (and
  bonusVsStatus's status key) with the creature's own variantStatus
  when the ability is fromCreature -- "each variant's signature
  status replaces the ability's fixed inflict."
- js/engine/pipeline.js / js/data/actions.js: action.damageType is
  now threaded from abilityCtx into the action object at both enemy-
  attack orchestrators (previously it was never populated at all, a
  real gap -- no enemy ability's own damageType, even once content
  tags one, could ever have reached calculateDamage). Every
  resolveDamageType call site that has an enemy creature in scope now
  passes creature.elementType too.
- js/data/enemyabilities.js: damageType: "fromCreature" on the 5
  abilities Tyler named (breath_weapon, catastrophic_breath,
  inherited_breath, elemental_strike, elemental_surge).
- js/data/bestiary.js: elementVariants on the Draven-Drak (5: Red/
  White/Green/Black/Blue), Skrel-Drak (4: Fire/Ice/Lightning/Acid --
  Heated Mist excluded, still flagged REVIEW/undecided in Tyler's own
  list), and Elementals (7: Fire/Ash/Stone/Plant/Water/Mist/Ice)
  families -- every creature in BESTIARY that uses one of the 5
  abilities above. A variant's `status` references the status id the
  Codex names even where STATUS_EFFECTS doesn't define it yet
  (shocked/corrosion/ashen_lungs/crushed/drenched/frozen) --
  applyAbilityInflict already no-ops safely on an unknown status
  (getStatusEffect returns null), so that content (the original
  spec's own step 3 item 4) lands with zero further wiring here.
- tools/audit.js: a new error-level rule -- a fromCreature ability
  used by a creature with no elementVariants. Verified it actually

  error, restored).
