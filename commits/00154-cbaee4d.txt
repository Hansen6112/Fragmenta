Two supporting fixes this surfaced:
- modifiersForHook now sets ctx.role = holderRole unconditionally --
  several call sites (rollToHit.defender's evasion/ally-miss phases,
  calculateDamage.tags) built their own ctx without a role field at all,
  which every new `when` clause reading ctx.role would have silently
  misread as undefined, incorrectly gating off the PLAYER's own existing
  behavior too (caught by phase1_step1b_pipeline_parity.js and
  fragmenta_6pc_tag_override_ledger.js).
- startCombat now deletes each ally's modifierState at the start of
  every fight, matching combat.player's own full per-fight rebuild --
  an ally's record otherwise persists across fights, so a once-per-fight
  flag (Guardian Spirit's used:false) would silently become "once ever"
  instead, a gap modifiersForHook's own comment had already anticipated.
