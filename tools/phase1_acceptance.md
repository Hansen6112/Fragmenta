## 3. Audit rules P1–P4

All four run as part of `node tools/tests/run_all.js`'s own `audit:`
line, currently **0 errors**:

- **P1** (step 1f): a combat creature's HP may only be written inside
  `applyAndReact`'s own call graph or `applyHeal`/`applyHealing` —
  catches an HP write that bypasses the pipeline's single accounting
  point.
- **P2** (step 1e): every action definition declares `targeting`,
  `toHit`, `actionType`, and (if `toHit: "roll"`) a real
  `PIPELINE_FORMULAS` key — catches an action added without the shape
  the generic resolvers depend on.
- **P3** (step 1h, new): no `*Legacy`/`resolveEnemyRetaliation`
  function, no `Object.defineProperty` on a combat object, no
  `combat.<field>`/`state.combat.<field>` alias spelling for a
  `PLAYER_FIELDS`/`PER_ENEMY_FIELDS` name, across
  `combat.js`/`pipeline.js`/`companion.js`/`resolver.js`/`data/actions.js`/
  `data/synergy.js` — guards against either deleted proxy, or any of
  the 15 deleted functions, reappearing. Verified to actually catch a
  regression (a deliberate `fooLegacy()`-plus-stale-alias injection),
  not just pass trivially.
- **P4** (step 1e completion): no code checks a specific action/ability/ally
  identity directly outside `PIPELINE_HOOKS`'s own name-based dispatch —
  catches a new mechanic re-introducing per-identity branching instead
  of going through the shared hook table.
